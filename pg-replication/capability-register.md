This register lists what the project has proved, with the result and the limit of each claim. It also lists what the project has not proved. A capability counts as proven only when a test has run and the result was observed. The detail of every run, with commands and numbers, is in the [evidence log](evidence-log.md).

The work ran on one machine with Docker Compose, PostgreSQL 16 and two nodes, `pg-primary` and `pg-standby`. The last evidence run was on 2026-11-25.

## Terms and identifiers

The register uses these terms. The write-ahead log (WAL) is the stream of changes that PostgreSQL replicates. The recovery point objective (RPO) is the amount of acknowledged data that may be lost. The recovery time objective (RTO) is the time that clients may be unable to write. A log sequence number (LSN) is a position in the WAL. A time to live (TTL) is the length of a lease. The Transmission Control Protocol (TCP) carries the replication connection. Coordinated Universal Time (UTC) is the time zone of every log. SIGKILL is the signal that stops a process at once. Shoot the other node in the head (STONITH) means stopping the old writer before promoting its replacement.

Each row has an identifier, such as REP-01. The prefix names the theme. Rows that start with GAP describe work that is not done.

The Evidence column says how many runs support the row and when the last run was. "Every check run" means that the fast checks run the test each time. "Count not recorded" means that the evidence log does not give a number. More runs make a claim stronger, and one run is a single observation.

## How to run the checks

`bash scripts/run-all-checks.sh` runs the fast checks. They are the Bash lint of every shell file, the document check, the Python standard, the hygiene check, the timeline check and the 17-step round trip.

The experiments change the databases and take longer, so each has its own runner. Each runner reports PASS or FAIL and restores the starting state.

- **Replication:** `test-replication-modes.sh`, `test-clone-rebuild.sh`, `test-rotation.sh` (about 16 seconds) and `test-maintenance-lock.sh` (about 25 seconds).
- **Failover and recovery:** `test-guards.sh`, `test-divergence-rewind.sh` (about 20 seconds), `test-rejoin-failure.sh` with `--control`, `test-point-in-time.sh` (about 2 minutes) and `test-hard-kill.sh --target roundtrip|restore|rotate` (minutes).
- **Detection, the actor and fencing:** `test-fencing.sh`, `test-detector.sh`, `test-auto-failover.sh`, `test-actor-kill.sh`, `test-actor-timed-kill.sh`, `test-two-actors.sh`, `test-controller-kill.sh`, `test-sync-after-failover.sh`, `test-lease-fence.sh`, `test-lease-failover.sh`, `test-lease-handover.sh`, `test-lease-failback.sh` and `test-resume-fence.sh`. Each builds the controller image on first use.
- **Faults and load:** `test-replica-lag.sh` (about 35 seconds), `test-slot-limit.sh` (about 2.5 minutes, writes 1.5 GB of WAL and needs 6 GB free), `test-network-faults.sh` (about 5 minutes), `test-link-faults.sh` (about 5 minutes) and `test-load.sh` (about 50 seconds).
- **Measurement:** `measure-recovery.sh` runs 21 trials of about 30 seconds, which takes about 13 minutes. With `--scenarios crash-matrix` it adds 12 trials of about 10 minutes. It writes the [recovery report](docs/recovery-report.md).

Closed gaps keep their numbers out of section 4. GAP-01 became RPO-01, GAP-02 became RPO-02, GAP-04 became FOV-09, GAP-05 became RTO-01 and GAP-06 became CRS-01. GAP-08 became DEC-01, GAP-09 became OPS-04, GAP-13 became SEC-R2 and GAP-14 became SEC-R3.

## 4. Open gaps

The gaps below belong to Phases 1 and 2. Everything that needs a client service moves to Phase 3, at the end of this section.

| ID | Gap | Why it matters | What would close it |
|---|---|---|---|
| GAP-03 | The write check (LEASE-04) is opt-in for each table and reads the node's own clock. It does not compare epochs between nodes. | GAP-11 | Real packet loss and reordering are not shown, because TCP hides them from Toxiproxy. | GAP-12 | The application layer is not built. It would hold the outbox, idempotent consumers, per-aggregate sequences and an independent invariant checker.
